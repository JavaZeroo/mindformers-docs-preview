分布式并行训练

动态图（PyNative）训练采用 多维混合并行 来训练大规模模型。所有并行维度统一写在配置文件的 parallelism 段中，加载时映射到 ParallelismConfig（见 mindformers/pynative/config/config.py）；mindformers/pynative/trainer/trainer.py 据此推导出数据并行规模，再由 mindformers/pynative/distributed/parallel_dims.py 的 ParallelDims 构建出一张多维设备网格（DeviceMesh）。各并行能力（FSDP/HSDP、TP、CP、PP、EP、SP）随后由 parallelize.py、tensor_parallel.py、context_parallel.py、pipeline_parallel.py、expert_parallel.py 等模块逐一施加到模型上。

动态图的设备网格（DeviceMesh）、FSDP/HSDP、TP/CP/EP、PP 调度等并行能力均由 HyperParallel 提供，是动态图训练的必需依赖（要求 MindSpore >= 2.8）。安装方式见 安装指南 · 安装 HyperParallel。

本页先给出 选型速查 与 可配项 vs 派生量 的全局约定，再按每个并行维度展开「① 是什么 ② 何时用 ③ 字段表 ④ 场景化完整 YAML」，最后给出组合约束与启动方式。

可配项与派生量：用户在 parallelism 中 真正需要配置 的并行度只有：data_parallel_shard、tensor_parallel、context_parallel、pipeline_parallel、expert_parallel、expert_tensor_parallel。

以下两个量 不是用户字段，由框架在 trainer.py 运行时推导，写在 YAML 里也会被覆盖：

  • data_parallel（数据并行总度）：由 world_size // (tensor_parallel * pipeline_parallel * context_parallel) 推导。

  • data_parallel_replicate（即 dp_replicate，HSDP 副本度）：当 data_parallel_shard < 0 时取 1；否则取 max(data_parallel // data_parallel_shard, 1)。随后 dp_shard 被回写为 data_parallel // dp_replicate。

因此你只需指定「分片度」data_parallel_shard，框架会自动算出副本度并组成 HSDP 拓扑；data_parallel_shard: -1 表示「用剩余卡数全部做分片」（副本度为 1，即纯 FSDP）。

全局配置示例与字段汇总

下面是一份覆盖主要 parallelism 字段的“总览型”配置，便于对照字段含义；实际使用时按后续各维度的场景示例裁剪即可。

parallelism:
  # —— 数据并行 / FSDP / HSDP ——
  data_parallel_shard: -1                 # 用户唯一需要配的 DP 字段；-1=剩余卡全部做分片(纯 FSDP)
  reshard_after_forward_policy: "default" # 前向后是否重新分片参数：always / never / default
  cpu_offload: False                      # 将分片后的参数/梯度卸载到 CPU
  disable_gradient_division: True         # 关闭 FSDP 自动梯度均分(按 sum 聚合)

  # —— 张量并行 TP ——
  tensor_parallel: 1

  # —— 上下文并行 CP ——
  context_parallel: 1
  context_parallel_method: "colossal"     # colossal / ulysses / hybrid
  context_parallel_async: False
  ulysses_degree_in_cp: null              # ulysses/hybrid 时按规则取值
  context_parallel_mask_type: "causal"

  # —— 流水线并行 PP ——
  pipeline_parallel: 1
  pipeline_parallel_interleave_num: 1     # 每个 stage 的交织模型块数
  pipeline_parallel_layers_per_stage: null   # pp>1 时必填：auto（均分）或各 stage 层区间列表，见 4.4
  pipeline_parallel_overlap_p2p: False
  pipeline_parallel_overlap_b_f: False

  # —— 专家并行 EP（MoE）——
  expert_parallel: 1
  expert_tensor_parallel: 1               # ep>1 时只能取 tensor_parallel 或 1
  moe_token_dispatcher_type: "alltoall"   # alltoall / alltoall_deredundancy
  npu_nums_per_device: 8

  # —— 序列并行 SP ——
  # SP 随 TP 自动开启，当前不支持单独关闭，无需在此配置（见第六节）

关于 data_parallel_shard_strategy：ParallelismConfig 中存在 data_parallel_shard_strategy（默认 "optim_grads_params"）字段，但在动态图代码中 没有任何消费点：FSDP 统一通过 fully_shard 一次性分片参数、梯度与优化器状态，分片粒度不可调。该字段当前为预留/占位项，改动它不会改变行为，新配置无需填写。

一、数据并行与 FSDP / HSDP

1.1 是什么

动态图默认采用 FSDP（全分片数据并行） 风格：在分片组内对参数、梯度、优化器状态做切分，前向/反向时按需 all-gather 权重、reduce-scatter 梯度。ParallelDims 把数据并行进一步拆成两层：

  • dp_shard（分片度）：组内对参数/梯度/优化器状态做切分——省显存，组内有 all-gather/reduce-scatter 通信。

  • dp_replicate（副本度）：组间整份复制权重、只在反向同步梯度——经典数据并行，通信少但不省显存。

两者都大于 1 时即 HSDP（混合分片数据并行）：节点内分片、跨节点复制，兼顾省显存与降低跨节点通信。FSDP 是否启用由 dp_shard > 1 或 cp > 1 决定（见 parallel_dims.py 的 fsdp_enabled）。

1.2 何时用 / 怎么选组规模

  • 基线：单机多卡训练直接用纯 FSDP（data_parallel_shard: -1，副本度为 1），把全部数据并行卡用于分片，显存利用率最高。

  • 显存不够：优先增大分片度（即让更多卡进同一个分片组）。极限情况叠加 cpu_offload、reshard_after_forward_policy: always。

  • 多节点想降低跨节点通信：用 HSDP——把分片度设为「节点内卡数」，让框架推导出「副本度 = 节点数」，分片通信走节点内高带宽，副本只做梯度 all-reduce。配置上只需把 data_parallel_shard 设成一个小于 DP 总度的正数。

1.3 字段表

字段

类型

默认值

说明

data_parallel_shard

int

-1

分片度（dp_shard）。-1 表示用剩余卡数全部做分片（纯 FSDP，副本度为 1）；填正整数则框架据此推导副本度，可形成 HSDP。

reshard_after_forward_policy

str

"default"

前向后是否重新分片参数：always / never / default。never 用显存换通信（前向后保留聚合权重，反向少一次 all-gather）；always 反之。default 等价于「非 PP 时 always、PP 时 never」。

cpu_offload

bool

False

将分片后的参数/梯度卸载到 CPU 内存，进一步省显存，代价是 H2D/D2H 拷贝。

disable_gradient_division

bool

True

关闭 FSDP 自动梯度均分：以 sum 而非 mean 聚合梯度（对所有 HSDP 子模块设 reduce op = “sum”）。

易错点：

  • disable_gradient_division=True 是默认值，意味着 FSDP 梯度按 sum 聚合而非取平均。量纲修正由框架在反向的 loss sense（1/(world_size//pp)）与 grad-norm 缩放里完成，无需用户手动设置任何缩放因子；不要误以为存在某个需要你配置的「梯度除数」开关。

  • reshard_after_forward_policy: default 在 PP 下解析为 never：因为 PP 每个 microbatch 都会重复前向，若每次都 reshard 会带来反复 all-gather，故默认保留聚合权重。

1.4 场景化配置

场景 A：单机 8 卡纯 FSDP（推荐基线）

8 卡全部做分片，副本度为 1。满足 dp_replicate(1) * dp_shard(8) * cp(1) * tp(1) * pp(1) == 8。

parallelism:
  data_parallel_shard: -1          # = 8（剩余卡全部分片）
  reshard_after_forward_policy: "default"
  cpu_offload: False
  disable_gradient_division: True
  tensor_parallel: 1
  context_parallel: 1
  pipeline_parallel: 1
  expert_parallel: 1

场景 B：双机 16 卡 HSDP（节点内分片 + 跨节点复制）

每节点 8 卡，希望节点内分片、节点间复制。把分片度设为 8，框架推导出 data_parallel = 16、dp_replicate = 16 // 8 = 2、dp_shard = 8。满足 2 * 8 * 1 * 1 * 1 == 16。

parallelism:
  data_parallel_shard: 8           # 节点内 8 卡分片；副本度 2 由框架推导
  reshard_after_forward_policy: "default"
  cpu_offload: False
  disable_gradient_division: True
  tensor_parallel: 1
  context_parallel: 1
  pipeline_parallel: 1

二、张量并行（TP）

2.1 是什么

tensor_parallel 指定 TP 规模，对注意力与 FFN 中的线性层权重在 算子内 做列/行切分（apply_non_moe_tp 用 ColwiseParallel / RowwiseParallel），组内通过 all-gather / all-reduce 同步激活。

2.2 何时用 / 怎么选

  • 单层权重在一张卡放不下、或单卡注意力/FFN 激活过大时启用。

  • TP 通信发生在 每一层的前反向，对带宽极敏感，通常只在单节点内 开（TP 组规模一般 ≤ 节点内卡数，如 2/4/8）。

  • 与 FSDP 正交：world_size = dp_total * tp * pp * cp，开了 TP 后剩余卡数自动用于数据并行。

2.3 字段表

字段

类型

默认值

说明

tensor_parallel

int

1

张量并行规模，1 表示关闭。

2.4 场景化配置：单机 8 卡 DP + TP 微调

tp=2，剩余 data_parallel = 8 // 2 = 4 全部用于分片（data_parallel_shard: -1 → dp_shard = 4）。满足 1 * 4 * 1 * 2 * 1 == 8。

parallelism:
  data_parallel_shard: -1          # = 4
  tensor_parallel: 2
  context_parallel: 1
  pipeline_parallel: 1
  expert_parallel: 1
  reshard_after_forward_policy: "default"
  disable_gradient_division: True

三、上下文并行（CP）

3.1 是什么

context_parallel 在 序列维 对输入进行切分，使每张卡只处理一段序列，显著降低长序列下的激活显存与注意力计算量；FlashAttention 在 CP 组内交换 KV 完成全序列注意力（见 context_parallel.py）。动态图支持三种实现方法 context_parallel_method：

方法

原理

约束（_validate_cp_method）

colossal

默认；按序列分块、组内交换 KV

无额外约束；ulysses_degree_in_cp 内部按 1 处理

ulysses

在注意力 head 维做 all-to-all 切分

要求 ulysses_degree_in_cp == context_parallel（不设则默认取 context_parallel）；context_parallel_async=True 时还要求 num_attention_heads % ulysses_degree == 0

hybrid

colossal + ulysses 混合

必须设 ulysses_degree_in_cp，且满足 1 < ulysses_degree_in_cp < context_parallel 且 context_parallel % ulysses_degree_in_cp == 0

3.2 何时用 / 怎么选

  • 主要用于 长序列/长上下文（seq_length 很大导致激活显存爆炸）。CP 组规模越大，单卡序列越短、激活越省，但组内 KV 交换通信也越多。

  • colossal：通用首选，序列切分直接，无 head 整除限制。

  • ulysses：在 head 维切分，更适合 head 数较多的模型；启用 async 时要保证 head 数能被 ulysses 度整除。

  • hybrid：把 CP 拆成「序列分块 × head 切分」两层，适合既想切长序列又想用 head 维并行的超长序列场景。

CP 与 FSDP 的耦合：启用 CP 时，FSDP 也会作用于 CP 组：分片网格名为 fsdp，规模为 dp_shard * cp，即便 dp_shard == 1（见 parallel_dims.py 的 fsdp_enabled / fsdp 属性）。也就是说开 CP 会自动让参数在 CP 组内分片，无需单独配置。此外 CP 输入准备仅接受 context_parallel_mask_type: causal，传入其它值会直接抛 NotImplementedError，且不接受自定义 attention_mask。

3.4 场景化配置

场景 A：单机 8 卡 colossal CP（长序列）

cp=2，剩余 data_parallel = 8 // 2 = 4 做分片。FSDP 分片组规模 = dp_shard(4) * cp(2) = 8。满足 1 * 4 * 2 * 1 * 1 == 8。

parallelism:
  data_parallel_shard: -1          # = 4
  tensor_parallel: 1
  context_parallel: 2
  context_parallel_method: "colossal"
  context_parallel_mask_type: "causal"
  pipeline_parallel: 1

场景 B：ulysses CP（head 维切分）

cp=4，ulysses 要求 ulysses_degree_in_cp == context_parallel。满足 1 * 2 * 4 * 1 * 1 == 8（data_parallel = 8//4 = 2）。

parallelism:
  data_parallel_shard: -1          # = 2
  context_parallel: 4
  context_parallel_method: "ulysses"
  ulysses_degree_in_cp: 4          # 必须等于 context_parallel
  context_parallel_async: False    # 若设 True，需保证 num_attention_heads % 4 == 0
  tensor_parallel: 1
  pipeline_parallel: 1

场景 C：hybrid CP（序列分块 × head 切分）

cp=4，hybrid 要求 1 < ulysses_degree_in_cp < cp 且整除 cp，故取 2。满足 1 * 2 * 4 * 1 * 1 == 8。

parallelism:
  data_parallel_shard: -1          # = 2
  context_parallel: 4
  context_parallel_method: "hybrid"
  ulysses_degree_in_cp: 2          # 1 < 2 < 4 且 4 % 2 == 0
  context_parallel_mask_type: "causal"
  tensor_parallel: 1
  pipeline_parallel: 1

四、流水线并行（PP）

4.1 是什么

pipeline_parallel 把模型 按层切分到多个 stage，配合 microbatch 流水执行。动态图固定采用交织式 1F1B 调度 ScheduleInterleaved1F1B（见 base_models/gpt/parallelize.py），通过 interleave 把每个 stage 切成多个虚拟模型块以减小流水线气泡。

4.2 何时用 / 怎么选

  • 模型层数很多、单卡放不下整模型时启用；常与 TP（节点内）、DP（节点间）组合成 3D 并行。

  • 增大 pipeline_parallel_interleave_num 可进一步减小气泡，但会增加 stage 间 P2P 通信次数；可叠加 pipeline_parallel_overlap_p2p 把通信与计算重叠。

微批数与调度策略（派生 / 预留）：

  • pipeline_parallel_microbatch_size 是派生量，不是用户可配项。trainer.py 会用梯度累积步数覆盖它：num_accumulation_steps = global_batch_size // (data_parallel * local_batch_size)（其中 data_parallel = dp_replicate * dp_shard 为数据并行总度），随后 pipeline_parallel_microbatch_size = num_accumulation_steps。所以请通过 global_batch_size / local_batch_size 间接控制微批数（见 配置文件说明），手填该字段无效。

  • pipeline_parallel_schedule（ParallelismConfig 中默认 "1f1b"）当前未参与分支：动态图固定走 ScheduleInterleaved1F1B，该字符串不被读取，属预留项。真正影响流水行为的是 pipeline_parallel_interleave_num 与 pipeline_parallel_overlap_p2p / pipeline_parallel_overlap_b_f。

int

1（派生）

派生量，运行时被 num_accumulation_steps 覆盖，无需手填（见上方提示）。

pipeline_parallel_schedule

str

"1f1b"（预留）

预留项，动态图固定用交织 1F1B，当前不参与分支。

4.4 场景化配置

pp > 1 时必须通过 pipeline_parallel_layers_per_stage 指定各 stage 的层放置，按层数能否均分选择以下两种方式之一。

场景一：层数可均匀放置 → 配置 auto

当 num_hidden_layers 能被虚拟 stage 总数（pp * interleave_num）整除时，配置 auto 即可，框架按虚拟 stage 顺序把层连续均分（每个虚拟 stage 分得 num_hidden_layers / (pp * interleave_num) 层）。例如 8 层模型、pp=2、interleave_num=2：4 个虚拟 stage 各放 2 层。

parallelism:
  data_parallel_shard: -1
  tensor_parallel: 4
  pipeline_parallel: 2
  pipeline_parallel_interleave_num: 2     # 虚拟 stage 总数 = 2 * 2 = 4
  pipeline_parallel_layers_per_stage: auto
  pipeline_parallel_overlap_p2p: True

若层数不能整除而仍配置 auto，启动时会报错并提示改用显式配置。

场景二：层数不能均分 → 显式指定各 stage 的层区间

列表每一项对应一个物理 stage（第 i 项给 pp_rank = i）；项内用逗号分隔出 interleave_num 段层区间，第 k 段是该卡的第 k 个交织模型块，对应虚拟 stage 编号 k * pp + i。区间写法为 "start-end"（闭区间）或单层 "n"，所有区间按虚拟 stage 顺序必须恰好覆盖 0 ~ num_hidden_layers-1 且层号递增。

以 10 层模型（层号 0–9）、pp=2、interleave_num=2 为例，10 % 4 != 0 无法均分，可显式配置：

parallelism:
  data_parallel_shard: -1
  tensor_parallel: 4
  pipeline_parallel: 2
  pipeline_parallel_interleave_num: 2
  pipeline_parallel_layers_per_stage:
    - "0-1, 4-8"    # 物理 stage 0：虚拟 stage 0 放层 0-1，虚拟 stage 2 放层 4-8
    - "2-3, 9"      # 物理 stage 1：虚拟 stage 1 放层 2-3，虚拟 stage 3 放层 9
  pipeline_parallel_overlap_p2p: True

层的执行顺序为虚拟 stage 0 → 1 → 2 → 3，即层 0-1 → 2-3 → 4-8 → 9。各 stage 层数可以不等（如本例为 2/2/5/1），可用于平衡首尾 stage 上 embedding / lm_head 的额外显存与计算。

五、专家并行（EP）

5.1 是什么

针对 MoE 模型（DeepSeek-V3 等），expert_parallel 把专家分布到不同卡，token 经 all-to-all 路由到所在卡的专家计算（apply_moe_ep_tp）；expert_tensor_parallel 进一步对专家权重做张量切分。EP 不是独立网格——parallel_dims.py 的 build_mesh 会按 EP 与 TP/CP 的相对大小，把 EP 通信组 复用 在 TP/CP 维上，并据此区分专家的 FSDP 网格 efsdp 与非专家的 fsdp。

build_mesh 分四种情形构造网格：

情形

EP 通信组复用关系

专家分片网格

ep == 1（含 etp == 1）

不构造 EP 维，experts 走普通 TP

与非专家一致（fsdp = dp_shard*cp）

ep <= tp

tp 拆成 tp_mod_ep × ep，EP 复用 TP 组内

efsdp = dp_shard*cp*tp_mod_ep

tp < ep <= cp*tp

EP 跨 CP 与 TP 组（cp 拆为 cp_tp_mod_ep × ep_mod_tp）

efsdp = dp_shard*cp_tp_mod_ep

ep > cp*tp

EP 进一步占用 dp_shard 维（efsdp 由 dp_shard*cp*tp/ep 得到）

efsdp 维度更小

5.2 何时用 / 怎么选

  • 仅 MoE 模型需要。专家数较多、单卡装不下所有专家时启用 EP；expert_parallel 越大，单卡专家越少、显存越省，all-to-all 通信越多。

  • expert_tensor_parallel 的语义：当 expert_parallel > 1 时它只能取 tensor_parallel 或 1。取 tensor_parallel 表示专家权重同样按 TP 切分（与非专家共用 TP 切分语义）；取 1 表示专家不做张量切分、只做 EP（etp 不启用，experts 仅按 EP 分布）。

  • alltoall vs alltoall_deredundancy：alltoall 是默认全连接 all-to-all 分发；alltoall_deredundancy（DeredundancyExpertParallel）用「节点间外层 all-gather/reduce-scatter + 节点内 all-to-all」的去冗余方案降低跨节点通信，仅在多机大 EP 时收益明显，并要求 expert_parallel >= npu_nums_per_device（否则 ParallelismConfig.__post_init__ 直接报错）。

5.4 场景化配置

场景 A：单机 8 卡 MoE，EP ≤ TP（专家随 TP 切分）

tp=4、ep=2（ep <= tp），专家张量并行取 tensor_parallel。剩余 data_parallel = 8//(4*1*1) = 2。满足 1 * 2 * 1 * 4 * 1 == 8。

parallelism:
  data_parallel_shard: -1          # = 2
  tensor_parallel: 4
  expert_parallel: 2               # ep <= tp
  expert_tensor_parallel: 4        # = tensor_parallel
  moe_token_dispatcher_type: "alltoall"
  context_parallel: 1
  pipeline_parallel: 1

场景 B：多机 16 卡 MoE，EP > TP + 去冗余分发

tp=2、ep=8（ep > tp），专家不再做张量切分故 expert_tensor_parallel: 1；用去冗余分发，要求 ep(8) >= npu_nums_per_device(8)。剩余 data_parallel = 16//(2*1*1) = 8。满足 1 * 8 * 1 * 2 * 1 == 16。

parallelism:
  data_parallel_shard: -1          # = 8
  tensor_parallel: 2
  expert_parallel: 8               # ep > tp
  expert_tensor_parallel: 1        # 专家只做 EP，不做 TP 切分
  moe_token_dispatcher_type: "alltoall_deredundancy"
  npu_nums_per_device: 8           # 要求 expert_parallel >= 此值
  context_parallel: 1
  pipeline_parallel: 1

六、序列并行（SP）

序列并行（SP）在 TP 的基础上，对 TP 未切分的部分（LayerNorm、Dropout、残差）按 序列维 进一步切分，降低这些算子的激活显存。

SP 随 TP 自动开启，当前不支持单独关闭：动态图 SPMD 路径中，只要开启 TP（tensor_parallel > 1）就会自动施加 SP：源码 base_models/gpt/parallelize.py 调用 apply_non_moe_tp 时形参 enable_sp 恒为 True。SP 没有独立的配置开关——parallelism 段下即便写了 sequence_parallel，当前也不会被该路径读取，因此既无需手动开启、也暂不支持关闭。

因此无需为 SP 单独配置：按本页第二节配好 TP（tensor_parallel > 1），SP 即自动生效。

组合约束

设备网格的总规模必须满足以下整除关系，否则 ParallelDims._validate / _validate_meshes 报错：

  • 总规模：dp_replicate * dp_shard * cp * tp * pp == world_size（world_size 即 msrun 的总卡数）。其中 dp_replicate 与 dp_shard 由框架按上文「可配项 vs 派生量」推导，用户只配 data_parallel_shard。

  • 数据并行总度：data_parallel = world_size // (tp * pp * cp)，必须 ≥ 1，且能被推导出的 dp_shard 整除。

  • TP / SP：tensor_parallel > 1 才有意义；SP 随 TP 自动开启（无独立开关，当前不支持关闭，见第六节）。

  • CP 方法：ulysses 要求 ulysses_degree_in_cp == context_parallel；hybrid 要求 1 < ulysses_degree_in_cp < context_parallel 且整除；ulysses + async 还要求 num_attention_heads % ulysses_degree == 0；CP 启用时 FSDP 分片组规模为 dp_shard * cp。

  • EP：expert_parallel > 1 时 expert_tensor_parallel 只能取 tensor_parallel 或 1；moe_token_dispatcher_type = alltoall_deredundancy 时要求 expert_parallel >= npu_nums_per_device。

启动

msrun --worker_num=8 --local_worker_num=8 --master_port=8118 --join=True \
      run_mindformer.py --config your_config.yaml --mode 1

--mode 1 表示 PYNATIVE（动态图）。--worker_num 即 world_size，须与上文整除关系一致。
